# Cross-system improvements — work in progress

This is a partial implementation, not an acceptance or release certification. Keep the current shared register and authorization boundaries; no patient, account or production data is reset or seeded. Clinical functionality must be validated with synthetic fixtures and professionally reviewed before use. The following status is specific to this branch.

1. **Completeness, quality and evidence:** existing role-scoped quality controls and a weekly missing-receipt count are not a global evidence audit. Receipt checkboxes are now described as attestations, not proof that a document was stored or verified; programme review milestones are no longer mislabeled as a 330-day ceiling or individual treatment duration. The quality page now states that it does not enforce report/export certification. Actual receipts, eTIMS invoices, M-Pesa/bank SMS and other supporting documents need a private attachment service with per-record authorization, size/type validation, malware scanning, retention, redaction, access audit and reliable deletion policy before uploads can be promised. SMS/bank data may contain sensitive third-party information; never add such examples to the public repository.

   **Legacy waiver security safeguard:** existing `dqIssues` records contain free-text findings/reasons without reliable scope metadata or server-owned provenance. Shared-system snapshot, paged and delta reads therefore withhold them, and direct creation, update and deletion are rejected. Existing server records are retained, not migrated or deleted. The hosted UI does not create, display, apply or export these waivers; quality findings remain visible. A secure replacement needs server-side role and record scope, validated decisions, versioning, retained history, auditing and migration review before waivers can be restored. This is a deliberate temporary loss of hosted waiver functionality, not completion of the global audit. Related historical audit-log text and other free-text collections still require a separate server-side scope/privacy audit.
2. **Monday deliberation and decisions:** the current secretary flow attests paper receipt, draws an order and marks discussion progress. It does not record acceptance/on hold/not accepted, an MCM-confirmed individual programme period, decision date, immediate action assignments, or advance conditional on the complete decision. These require server-owned commands, authorization, optimistic versions, retained changes, scoped recipient notifications and tests; no status should be inferred from paper receipt or discussion alone. They must not bypass the existing MCM office enrollment decision.
3. **Caregiver plan and review:** this branch adds fixed, local, non-editing reflection prompts to the authorized PDCA editor. These are not trained on the requested 120 reviewed PDCAs, do not inspect or summarize patient text, do not make clinical recommendations, and do not replace an MCM review. The collection has not been supplied or approved for training. A future trained system requires lawful use of the records, an approved processor and clinical/privacy/security assessment; do not send patient data to an unapproved external AI. Structured care-plan items, per-item details, assignment, escalation and verified MCM-confirmed duration are not implemented here.
4. **Month boundaries:** the scoped Monday financial review breaks the previous Monday–Sunday paid/reconciled KES totals into calendar-month segments using actual Nairobi dates, including a food/foodbag subtotal. The food calculator labels the current Monday–Friday calendar-month segments and warns that its weekly estimate is not automatically allocated or a recorded expense. This does not create monthly purchase commitments or prorate forecasts. A true purchase must still be recorded and assigned to the correct month under existing controls.
5. **Handwriting:** stylus capture, handwriting recognition, proofing and signature integrity are not implemented. Do not claim that typing or a pasted image proves a physical signature. Any future recognition must run in an approved environment, require user review and preserve original strokes alongside the corrected text with clear provenance.
6. **Speed:** tests and limited calculations are not proof of 100% effectiveness. Benchmark with representative authorized data and target devices before making performance claims; do not weaken access checks or durability for speed.
7. **Announcements:** existing notifications are not a complete scoped announcement and sound/highlighting system. Design authorization, recipient resolution, privacy, delivery/read state, quiet hours, opt-in accessible sound, and safe offline behavior first.
8. **Icons:** existing role navigation is permission-filtered but a comprehensive context/icon audit across all account views and devices is still required.
9. **Drawers and master archive:** existing report history and scoped patient access are not a complete Care Cycle File or master-archive access notification. A future archive must keep role/county/area/patient scope, append immutable access events and deliver appropriately scoped administrator notifications without disclosing clinical content to unauthorized administrators. A notification is not permission to access a record; do not bypass RBAC.
10. **International advisory:** the current system provides explicitly shared, MCM-authorized PDCA revisions and line-anchored advisory discussion; this is not the complete requested international medical workspace. Expand only with server-enforced authorized sharing and no unshared patient data.
11. **Referral and Care Cycle File:** current discharge information and report exports are not a complete cycle-wide file or public export. Add source-linked referral organization and support, complete cycle gathering, purpose/audience/consent selection, legal review, redaction, provenance, and scoped audited export before offering public viewing. Never label confidential patient data public by default.
12. **PDCA formats:** based on existing programme-day policy, this branch removes the four extended-stay justification prompts from normal (<120-day) editor forms and does not require them at submission; the estimated discharge date and all other required fields remain. At 120+ they remain mandatory, with the pre-existing MCM review and authorization chain. At 180+ a saved report is labelled 180-Day. Older recorded justification is preserved and shown as retained history. A draft crossing day 120 must be reopened and completed before submission. Classification still uses the existing programme-day/milestone policy, **not** the requested individual MCM-confirmed deliberation period, which is not implemented. The established supported-hospitalization MCM-preparation policy also remains unchanged.
13. **Search and AI:** existing search/assistant functions are not guaranteed to cover every authorized record, and must not expose unshared clinical data or make unverified medical claims. Indexing, authorization, freshness, audit, evaluations and lawful AI processing remain to be designed.
14. **Device layouts:** this branch repairs the policy-card heading wrapping and preserves the expanded desktop navigation until deliberate workspace use. Shared workspace section tabs now have quieter theme-aware styling, wrapping and visible keyboard focus; patient-record sections also have contextual icons and an announced current section. Synthetic browser checks cover patient tabs at five widths, all nine available MCM destinations, 45 built-in themes with three tab styles and three colour schemes, and a small sample of other workspace tab groups on a phone viewport. Full PC, Samsung tablet, mobile, zoom, keyboard and assistive-technology acceptance across every account has not been completed.
15. **PWA:** the web manifest names the standalone application CareLink and retains the existing app icons. Browser/OS installation and identity behavior varies; a PWA is not a native Android application, and the system cannot promise that the operating system will never display browser branding. The separate native Android application remains a preview without production workflow or security parity. Secure hosted offline access remains blocked; see `OFFLINE_SECURITY_REQUIREMENTS.md`. Cached shell or legacy outbox is not secure offline clinical access.
16. **Pane behavior:** in desktop pane layout, selecting a pane destination navigates immediately and expands/holds the pane through programmatic redraw and scroll restoration. Deliberate interaction, wheel or touch in the workspace folds it when automatic folding is enabled; a pinned-open preference is respected. Narrow-screen navigation remains a drawer. Actual touch/keyboard and browser acceptance is still required.
17. **Pane audit:** existing role navigation regression checks 36 seeded roles for authorized destinations and duplicates; this is not an organizational determination of which accounts should never have a pane. Users retain the existing Tabs preference. Do not hide an authorized destination without a role-specific replacement and an agreed account list.
18. **Policy card overlap:** status badge and classification metadata now wrap independently, with constrained children on small/zoomed layouts. This addresses the reported policy-card template; a global rendered visual audit and physical-device acceptance remain outstanding.

## Report printing and preview work

- The general report print action now copies the visible report document into a print-only container; workspace banners and controls are excluded. The print copy expands chart-data details, applies A4/Letter orientation, wraps table cells, repeats table headers and permits long tables to paginate. The original preview remains unchanged. Other workspace print actions retain workspace printing, and document-modal printing uses the same isolated copy.
- Archive entries currently retain generation metadata, not immutable report contents: reopening or downloading them reconstructs from current data. The archive, on-screen report, printed report and Word download now disclose this; the metadata checksum does not certify report data. Non-patient-figures CSVs are explicitly labelled metadata CSVs, not complete report exports. Missing or unauthorized archive IDs cannot fall through to a generic preview or export. This is not a complete archival or report-generation audit.
- Synthetic Chromium PDF checks exercised the actual patient-figures report augmented with a 125-row table and chart, on desktop and phone-sized viewports in both A4 orientations. Extracted PDF text contained every synthetic row, chart labels and report ending, with no workspace header/banner, and text bounds stayed within page dimensions. An additional synthetic document-modal PDF remained isolated. The optional `npm run test:browser:report-print` needs Playwright Core, Chromium and the Python `pymupdf` package; set `CHROMIUM_PATH` and, if installed outside the environment, `PDF_PYTHONPATH`. These tests do not establish that every report, exceptionally wide table, oversized cell, PDF reader or physical printer works correctly. Review the device print preview and test physical A4 printers before acceptance.
