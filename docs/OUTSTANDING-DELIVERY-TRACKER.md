## Safety and release rules

- Do not deploy draft PR #75 as a completed upgrade. Its held-work review, quality waiver safeguard, report printing, cycle manifest and other changes are partial and not merged into main at the time this tracker was written.
- Hosted offline clinical login is not approved or enabled. The legacy outbox is unencrypted and can lose refused work or falsely acknowledge partially rejected work. Do not rely on it for secure or durable clinical work. Do not clear browser storage, reset/recommission the shared installation, seed production, or delete held work as a shortcut.
- Every clinical/data-access change requires server-side authorization and scope, synthetic security and regression tests, plus clinical/privacy review as appropriate. Never infer approval, consent, signatures, paper delivery or historical facts from a UI action.
- Do not publish real patient information, private organizational documents or credentials in this public repository. Real-data verification uses an approved private process.
- Release only individually reviewed, tested and authorized changes; keep unmet items open. A passing build or Vercel preview is not clinical, security, privacy or physical-device acceptance.

## Subsequent 16-point request — staged, not complete

See [request traceability](REQUEST-TRACEABILITY.md) for the reconstructed numbered references and evidence. The original numbered text is not in the available context; exact line-by-line completeness cannot be verified until it is provided.

- **Sessions:** Explicit logout attempts to release the server lease; investigate failed release and safe multi-tab/device takeover. Browser tab closure cannot reliably notify the server, and refresh or a background tab must not silently terminate other work. No immediate tab-close guarantee has been implemented. [Session handoff design gate](SESSION-HANDOFF-DESIGN-GATE.md) records the current token/lease limitations, proposed fencing requirements and required tests; it does not enable takeover.
- **Documents — in progress, not secure sharing:** The hosted `api/index.js` has no `/api/files` implementation. The older standalone `v6/server.py` file list, upload and download routes require a session but do not enforce document-level patient or recipient authorization, and do not scan uploads. The user chose to keep the legacy routes running and preserve existing files. The client now warns about this exposure, checks metadata scope, does not mark a failed file open as successful, verifies upload receipts and avoids creating a document record after an unconfirmed upload. These client-side checks do **not** secure direct legacy server requests. The user has clarified that private storage and malware-scanning services are not yet available: defer integration, but retain both as future build needs. Secure scanning/uploads, editing, personal libraries and selected user/department/team sharing (including tags, notes and the TB-completion example) still require approved private storage, malware scanning, server authorization, audit and migration/recovery. No real file was accessed or migrated.
- **Navigation, transitions and boxes:** Patient-record tabs now focus and reveal their selected section. Patient metadata and the executive action matrix have container-aware layouts; synthetic browser checks cover selected narrow and wide containers, not all workspaces or devices. Global click/scroll behavior, transitions and other boxes remain to be audited.
- **Public statistics:** Central data and publication rules, approval, disclosure thresholds and suppression remain open. Existing public figures must not be treated as authorized live aggregates.
- **Patient count and completeness:** The existing 4,000-patient reference set is synthetic. The requested 4,444 real-patient figure and all real patient/program/user completeness require authorized private reconciliation and provenance; no real records have been created or modified. The patient metadata card no longer asserts 100% completeness or fabricates GPS accuracy.
- **Foundation C-DIMS Coins:** The page now explains the five weighted proxy indicators and their limits and improves standings layout; it does not establish an independently validated measure of accuracy, timeliness, effectiveness, efficiency or disciplined performance. Workload/role fairness, scoring design, rewards governance and independent verification remain open.
- **Account identities and contrast:** The screenshots identify the navigation identity block and the workspace greeting banner. The default account signature now derives stable colors from the account ID for both bands; explicit personal color choices remain respected. It is a visual cue, not proof of identity: hash collisions and perceptually similar colors are possible, and accounts can intentionally choose the same palette. The role dot has padded space and an in-box outline to avoid clipping. Synthetic tests cover 93 default account signatures and gradient-stop contrast; browser geometry covers six synthetic roles at four widths with light/dark themes. Coins hero text also has a targeted contrast improvement. A comprehensive contrast and real-account/device accessibility audit remains open.
- **Department naming and reporting:** The media console title is now Media & Information Governance; the hospital liaison Monday navigation label is Hospital Department Update. The latter still opens the existing Monday meeting and is not yet a dedicated, complete hospital/clinical reporting workflow. Scope, authorization and reporting content remain open.
- **Release evidence:** This staged UI change includes non-browser regressions and an optional Chromium synthetic geometry/navigation test; physical device, accessibility, clinical and live-account acceptance remain outstanding. Record the merged PR and production deployment separately when confirmed.
