# Demonstration register specification

The board-preview and reference register is a fixed, synthetic dataset. It is
generated by `seedOfficial()` in `v6/src/data6.js` from one object —
`DEMO_REGISTER` — and every screen, seeder default, API check and published
master file reads its size from there. This page records what the register
contains so a reviewer can check a running installation against the
specification rather than against a screenshot.

**No real patient record is used.** Names, telephone numbers, national
identifiers, GPS coordinates and clinical values are generated with reserved
ranges. See `README.md` → *Personal data*.

## What the register contains

| Property | Value | Where it is enforced |
|---|---|---|
| Patients | **4,000** | `DEMO_REGISTER.patients`; `DB.seedOfficial`, every default call site, `api/index.js` `REFERENCE_PATIENT_COUNT` |
| Age range | **5–75**, every age present | `seedOfficial()` age draw (a quarter children 5–17, the rest 18–75) |
| Sex split | **2,000 girls / 2,000 boys** | alternating `sex` draw |
| County split | **Kisumu 2,000 / Homa Bay 2,000** | `balancedArea()`, alternating across the 10 ministry areas |
| Day 60–80 review window | **1,600 patients (exactly 40%)** | `DEMO_REGISTER.windowShare` |
| Remaining patients | day 81–240 core, day 241–330 extension tail | `PROGRAM_DAYS_PROFILE` / `DEMO_REGISTER` |
| Recorded contacts per patient | **at least 12** | `DEMO_REGISTER.minVisits` |
| Home-visit rhythm | **every 21 days** from enrolment to today | `DEMO_REGISTER.visitIntervalDays` |
| Weighed measurements per patient | **at least 3**, never more than 21 days apart | `DEMO_REGISTER.minWeights`, `weightDates` grid |
| Modules | every programme and departmental collection populated | `enrichV6Collections()` |

Because 40% of the register was enrolled only 60–80 days ago, those patients
have three or four three-weekly home visits behind them. They still carry at
least twelve recorded contacts because a patient in early active care needs
extra clinical contacts between the regular home visits — wound dressing,
medication review, an escorted hospital appointment. Those extra contacts are
recorded as `clinical` (or `hospital`/`homestay` where the care plan says so)
on their own days. The regular `home` visit and its weight stay on the
three-week grid, which is what the Foundation's trial report asks for: a weight
at least once every three weeks, with flexible scheduling in between.

## Where the same number appears

- `v6/src/data6.js` — `DEMO_REGISTER`, the seeder default, `db.meta.label`.
- `v6/src/core.js` — a fresh browser-only boot seeds the same register.
- `v6/src/app.js`, `entry6.js`, `dev_console6.js`, `import.js`,
  `care6_flows.js`, `views_settings.js` — operator copy and auto-feed gates.
- `api/index.js` — `REFERENCE_PATIENT_COUNT`, the import audit line and the
  completeness check labels.
- `v6/tools/build_reference_master.js` — the published package.
- `public/master/CareLink-Reference-Master-v6.6.json` — the file the Chief
  downloads in *System → Master data import*.

`v6/test/v699-demo-register-spec.js` asserts every row of the table above
against the real seeder and the real published package, and fails if any module
starts advertising a different register size again.

## Why the register is not stored inline in a request

The register is 83 MB of JSON. It is published as a Brotli package of about
2.25 MB inside six verified upload chunks, well under Vercel's 4.5 MB Function
request limit and Upstash's per-request limit. The live state itself gzips to
about 3.8 MB and is written in eight KV shards of 700 KB, inside the sixteen-shard
recovery ceiling. Nothing about the register is inline in the application bundle;
the bundle only knows how to generate and verify it.

## Checking an installation

1. Sign in as the Chief System Administrator.
2. Open **System → Master data import**. The quality panel must show 4,000
   patients, 100% registry completeness and zero findings.
3. Open the Master Patient Register: the caseload headline reads 4,000, split
   2,000 Kisumu / 2,000 Homa Bay.
4. Rebuild the package at any time with `npm run build:reference-master`; the
   build refuses to publish a package that fails its own completeness checks.

Regenerating from a different seed date changes nothing above: the
specification is a property of the seeder, not of the calendar.
