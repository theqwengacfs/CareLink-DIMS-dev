# 16 · CareLink DIMS v5.1 · Release report

**Date:** 22 October 2026 (second increment on the 20 October build)
**Build:** 5.1.0 · schema 5 (unchanged, no data migration)
**Artefact:** `LOMAMO-CareLink-DIMS-v5.1.html` (1,072 KB, one file)
**Kit:** `LOMAMO-CareLink-DIMS-v5.1-Offline-Kit.zip`
**Target screen:** Samsung Galaxy Tab A11+ 5G (SM-X236), 11 inch, 1200 x 1920, 16:10, 90 Hz

This report states what was built, what was checked, what broke while it was being built, and what has
not been checked at all. It does not claim more than the tests and measurements show.

---

## 1. What this release adds

| Area | What now exists | Where |
|---|---|---|
| Workspace themes | Nine personal themes plus "match this tablet": Foundation (default), Daylight (the v5.0 look), Savanna, Lake Victoria, Canopy, Jacaranda, Night ward, Midnight gold, High contrast | `src/themes.js` |
| Corrected accents | Two accent colours per department: a fill (white text 4.5:1 or better) and a foreground (4.5:1 or better on the theme surface) | `WTHEME.accents()` |
| Navigation pane | One pane per console, built from `navModel()`, role-first ordering, foldable groups, icon rail, drawer on narrow screens, personal choice of pane or tabs | `src/navpane.js`, `src/console51.css` |
| Tablet layer | Touch targets of 44 px or more on coarse pointers, a Large option (56 px), working text size (90 to 125 percent), safe-area insets, focus rings, no hover dependence | `src/console51.css` |
| Preferences | Theme picker with miniatures, navigation, tablet comfort, organisation defaults (system.config only) | `src/views_settings.js` |
| Print and paper | Printing and the lock card always render as light paper, whatever the theme | `console51.css` |

Public pages (landing, sign-in, public portal) are always drawn in the default look. A person's theme
belongs to their console only.

## 2. What it does not change

Permissions, data, workflows, audit, sync and the server are unchanged. A theme changes colour and
contrast only. A status keeps its hue and always carries its written label; in the dark themes the shade
moves so the label stays readable.

## 5. What has not been checked

- **No physical Galaxy Tab A11+ was used.** Everything above is Chromium with device emulation. The
  device's real CSS viewport width is not confirmed (800 or 1200 are both plausible at that density).
  The layout rules are width-based, so a 1200 px portrait view would show the persistent pane rather
  than the drawer. Please open it on the tablet before relying on it.
- **Samsung Internet, DeX and Android WebView** were not tested. CSS `zoom` (text size) and `color-mix`
  need a current Chromium engine.
- **The contrast audit is not the whole application.** It covers 11 representative pages in all 9
  themes. About 70 views exist. Text on image backgrounds is skipped. Non-text contrast (icons, borders)
  was only enforced for High contrast form fields and for chart colours.
- **Theme preferences across two devices.** Preferences live in `personalPrefs` and are saved with the
  database, but a two-device sync of a theme change was not tested.
- **Actual printing** of report documents was not performed; print styling was checked by emulation.
- **90 Hz smoothness and first-load speed** were not measured. The file grew from 1,026 KB to 1,072 KB.
- **Other organisation-wide settings** (for example `notifications.*`, `security.*`, `ai.*`) still reach
  `SETTINGS.set()` without a capability check. Only `density`, `accentMode` and `consoleTheme` are guarded.
- **Foundation website colours.** The site's page text did not expose its palette, and the sandbox could
  not download its assets. The Foundation theme is derived from the logo and the navy and gold already
  used in the project, not from the website's stylesheet.
- **"High fidelity sheets"** was read as the tab sheet, page tabs and data tables. The Excel and Word
  exports were not redesigned.

## 6. Decisions the owner may want to reverse

| Decision | How to reverse |
|---|---|
| Default theme is Foundation, so every console looks different from v5.0 on first sign-in | Settings, Appearance, Organisation defaults: choose Daylight. Or set `consoleTheme` |
| Default navigation is the pane, and the tab sheet is hidden on wide screens | Each person can choose Tabs under Navigation. To change the default, edit `NAVP.prefs()` |
| A page without its own condition inherits its group's | `navModel()` in `src/ui.js` |

### 7.2 Messaging: defects found and fixed

| # | Defect in v5.0 | Effect |
|---|---|---|
| 1 | A reply reused the first message's recipient list | **The original sender never saw the reply** (reproduced: 1 message instead of 2) |
| 2 | `markRead` was never called | Unread counts never cleared |
| 3 | `send()` ignored its own screening result | A blocked message could still be stored by any caller |
| 4 | `send()` had no capability check | A read-only role could send by calling the action |
| 5 | Recipients came from the caller, and a department message went to that department in **every county** | Cross-county leakage; forged thread ids |
| 6 | Reply form took the thread id from the page | Any thread could be written into |
| 7 | Phone screen only matched 07xxxxxxxx | +254 and 01xx numbers passed |
| 8 | Flagged-message count was shown to every role | Count leaked outside HR |
| 9 | Contact avatars were white text on a transparent background | Initials never visible, in any theme |

All of this now lives in the data layer: `MESSAGING.route()` works out recipients, `send()` checks the
capability, screens the text and refuses anything out of reach. The existing v4.2 test used the
placeholder thread `dm:test`; it now uses a real thread id because the contract is stricter. Its
intent (a message is stored, audited and notified) is unchanged.

### 7.3 The 300 second policy

Both the browser (`SESSION.END_AT = 300`, warning at 285) and the host (`CARELINK_IDLE_SECONDS`
default 300) were 60 seconds before. `v42.js` pinned 45 and 60, and was updated on purpose because the
stated policy changed, not to get green. The idle timer no longer defers to the lock screen, which
could previously stop the sign-out from firing. Verified in a real browser with a controlled clock: no
warning at 284 s, warning at 286 s, still signed in at 298 s, signed out by 302 s with the audit entry
"Ended after 300 seconds without activity", and genuine activity resets the clock.

### 7.4 Back, Forward, Previous, Next

* **History:** Back and Forward in the top bar, Alt+Left and Alt+Right, and the tablet's own Back
  gesture, all on one stack (60 deep, cleared at sign-out). Verified in a real browser.
* **Page:** under every console page, Previous and Next follow the account's own pane order and show
  "Page n of N". They can only reach pages the pane already lists.
* **Record:** Previous and Next patient, Previous and Next conversation.
* **Tab:** Previous and Next section inside a patient record, inside Settings, and across the request
  status filters. The patient register already had its own paging.
* Not covered: the PDCA and assessment stage displays (they show progress, not navigation), and
  steps inside pop-up forms.

### 7.5 Creative Studio

Personal choices for corners, typeface, backdrop, hero panel, card style and accent colour, plus seven
presets (Clinic day, Night shift, Field in sunlight, Lake calm, Presentation, Woven, Minimal) and
Surprise me. Values are validated against a table, stored per person and never shared. Every accent is
passed through the same contrast correction. Fonts are system fonts, so nothing is downloaded.
Backdrop patterns were made fainter after the audit showed they could lower text contrast. Audit:
0 failures across all presets and random combinations.

### 7.6 Navigation follows the account

`navModel()` uses the account's own permissions, so grants, denials and delegations change the pane.
Tested by removing each held capability from each role in turn: **345 account variants, none offered
a page that answers "Access denied"**. Delegations offer the page while active and withdraw it when
they expire.

### 7.7 The offline kit and firewall rules

New `firewall/` folder: `FIREWALL-RULES.txt`, `windows-allow.bat`, `windows-remove.bat`,
`linux-firewall.sh` (ufw, firewalld, iptables, nftables) and `macos-firewall.sh`. Each opens **one TCP
port, to the local subnet only**, has a remove option, and refuses public ranges. Linux and macOS have
`--dry-run`. The Linux script prefers the default-route network and skips Docker and virtual
interfaces. Fixed in the existing kit: the Windows rule was open to any address and its name did not
match what the network-status tool looked for.

**Joining the host.** A completely empty tablet cannot join: the host refuses to hand its database to a
device that has not signed in, and sign-in needs a local user list. A device joins by seeding the
demonstration set or restoring a backup first, signing in, and then adopting the central copy. This is
by design but should be understood before deployment. **Before real accounts connect**, set per-account
passwords with `tools/set_password.py` and start the host with `CARELINK_ALLOW_UNVERIFIED=0`;
otherwise accounts without a host password are accepted.

### 7.8 Further defects found by the wider audit

Text coloured with the raw accent fill (10 places) was unreadable on dark themes; selected segmented
controls had white text on a light fill in dark themes; two group labels used a decorative grey; the
patient-record back button pointed the wrong way; the assistant button covered the pager's Forward
button. Each is fixed, and a static test now fails if a text use of the raw accent returns.

### 7.9 Still not checked

* No physical Galaxy Tab A11+, Samsung Internet or DeX.
* The Windows and macOS firewall scripts were reviewed and unit-tested only as far as their logic can
  be on Linux (macOS subnet arithmetic and command construction in dry-run). They were **not run on
  those systems**. The Windows script was not executed at all.
* The multi-device test used several browsers on one machine, not separate tablets on Wi-Fi.
* The contrast audit covers 13 representative pages in 9 themes plus the studio, not every view.
* Router settings (client isolation, DHCP reservation) are documented, not tested.
