## 3. Defects found and fixed during the build

These were found by the tests, not by reading the code.

1. **A schema/generator mismatch in the interaction test.** The two medicines chosen for the
   "severe interaction" test were not flagged as severe in the formulary. The test was wrong,
   not the engine; the test now uses a pair the formulary actually flags, so it proves the
   refusal rather than the absence of one.
2. **Leave approval blocked itself.** `decide('approved')` re-ran the coverage check without
   excluding the request being approved, so every approval reported an overlap with itself.
   `check()` now takes `ignoreId` and `decide()` passes the record.
3. **A one-person approval chain.** An HR officer could apply for a colleague and then decide
   the same application, because the employee had no user account. The engine now refuses a
   decision by whoever recorded the application.
4. **A Monday that hid the field.** The coverage board showed one row on a Monday, which was
   correct (the office day) but made the test's assumption wrong. The baseline pattern was
   rebuilt so every field location appears on the days it is actually staffed, and the test
   now checks the week, not a single day.
5. **Exports reported success without a file.** `DOCEXPORT` returned `true` even when the
   browser had blocked the download. Every export now returns an explicit result and the
   console reports "blocked" as blocked.
6. **`submit-upload` claimed a file it never stored.** The upload form had a file input and
   ignored it. The handler is now asynchronous, stores the bytes on the host, records the
   digest and retention class, and marks the record as having no file when the host is
   unreachable.
7. **A duplicate `renderLeave`.** Moving leave into `leave.js` left the old function in
   `views_admin.js`; the later definition silently won. The old one was removed and the test
   lint now names detail views explicitly.
8. **The print path printed the console.** The printable document sat inside a modal, so the
   sidebar and buttons could appear on paper. It is now written to a body-level container and
   `@media print` hides `#root`.
9. **Client and host disagreed about a password.** The browser hashed the password into the
   document; the host accepted any name. The host now verifies its own salted PBKDF2 hash when
   a credential is provisioned, the client passes the password once, in memory, and a session
   that expires asks for it again rather than failing silently.

## 4. Browser and host verification

After the build was green, the application was driven in a real browser (Chromium 156,
headless, 1440 x 900 and 820 x 1180) against a local HTTP copy and against a TLS host with a
self-signed certificate. What was observed, not inferred:

| Check | Result |
|---|---|
| Sign-in landing and demonstration dataset | Renders; the dataset loads; every demonstration account appears |
| Console shells | 30 navigation entries render for the Medical Case Manager; no page errors on any screen visited |
| Patient clinical tab | Renders; the allergy banner reads "Recorded allergies: Penicillin, Sulfa" |
| Prescription screen | Refuses amoxicillin for a penicillin-allergic patient, with the reason in the toast, and records nothing |
| Prescription and dispensing | A safe medicine is prescribed, then dispensed, and the record moves to `dispensed` |
| Visit planning | "Propose next week" produces a draft; "Accept" places the visit on the calendar; the button disappears |
| Paper forms | The patient picker opens; the editor opens with the patient prefilled |
| Leave, care plans, pharmacy, forms consoles | Render at desktop width with no clipped controls after the table fixes |
| Tablet width (820 px) | The sidebar collapses; forms and console stack in one column |
| TLS handshake | `https://127.0.0.1:8443/api/health` returns 200 with `"tls": true`; TLS 1.1 is refused |
| Server password | Over TLS: wrong password 401 `bad_password`; missing password 401 `password_required`; correct password 200 `verified: true` |
| File round trip over TLS | A file uploaded from the browser returns byte-identical content and the same SHA-256 |
| Session protection | The file endpoint answers 401 without a session token |

Two defects were found by that pass and fixed: a row of controls in the clinical summary was
clipped inside its card, and the reorder count treated every formulary item as "out of stock"
in a county that had never stocked it.

## 5. What has not been verified

1. **No physical device.** Chromium at tablet width is not a Samsung A11, and no touch
   gestures, soft keyboard or screen rotation has been exercised. Nothing has been opened in
   Safari or Firefox.
2. **No certificate from a real authority.** The TLS handshake was tested with a self-signed
   certificate on localhost. No chain issued to the Foundation has been loaded, and no tablet
   has been traced through the handshake over the office Wi-Fi.
3. **The DOCX and XLSX files have not been opened in Microsoft Word or Excel.** They are
   structurally valid OOXML stored-ZIP packages and the writer is exercised by tests, but
   "valid ZIP with the expected parts" is not the same as "opens without a repair prompt".
   Open one of each on the office machine before relying on them.
4. **No real data has been imported.** The import engine and its eleven checks pass against
   synthetic rows. The real workbook has not been seen.
5. **The Omaha problem list is a subset.** It is labelled as such on screen. It is not the
   licensed full scheme and must not be presented as it.
6. **Leave names are placeholders.** The staff names in the leave specification were carried
   exactly as supplied. They are not a verified staff list.
7. **Homa Bay still carries Sofia.** The organogram does not show it; the system flags it as
   unverified and asks for a decision rather than deleting a location someone may be using.
8. **Document bytes need the host.** On a device with no host connection the record is saved
   but the file is not, and the console says so. There is no device-local file vault yet.

## 7. Honest summary

The system is materially more complete than v4.1: the largest documented gap (pharmacy), the
second (scheduling) and the third (leave balances and document storage) are now implemented
and tested. The console has been driven in a real browser, and the host has been tested over
TLS with a self-signed certificate, including a password refusal and a file round trip. What
remains outside what can be claimed from this machine: a physical tablet pass, a certificate
from a real authority, and opening the generated Office files in Office. Those are the next
three tasks, in that order.

## 8. Addendum: the tablet and half-second round

Written after the 5.0 build, when the requirement changed from "opens on a tablet" to
"designed for the tablet in the hand, refreshing twice a second".

### 8.1 The navigation rail was removed

The tall dark panel that listed every console module is gone from the product, not hidden.
The console now carries a horizontal sheet of tabs, one for each module the signed-in role
may open in that console, plus "All", which opens a page map grouped by the same sections.
A module that the console does not use is not in its sheet and is not in its map. The root
element is `div.app.shell`; the old `.nowrap` class was abandoned because it collided with a
global utility and forced the page to 639 px on a 360 px phone.

### 8.2 The half-second refresh, and the defect that blocked it

The first implementation was written, built and tested, and it failed. Two devices loaded
the same central copy and then nothing moved. The cause was not the refresh loop:

1. `SYNC.start()` asked for `/api/state` before any session token existed. The host answered
   401, so the client concluded "Central database unreachable" and stopped. The refresh loop
   was running against a sync layer that had never joined the host.
2. A device that had seeded the demonstration set locally held records the host had never
   seen. On first contact the join table correctly called that a conflict, and the conflict
   dialogue waited for a human. On a fresh installation that is the normal state, so the
   first device could never join.

Both were fixed at the cause. The session token, once issued, restarts the join instead of
waiting for the next save. A local copy that is demonstrably synthetic (`meta.demoSeeded`)
is adopted away without a dialogue; a copy holding unsynced real work still raises the
conflict. The live layer also takes the host copy on its first tick, whatever its revision,
so a standby tablet never starts from a stale record. The save debounce was cut from 500 ms
to 120 ms, since the half-second promise includes the write. Measured afterwards, with two
Chromium instances against the host, a record added on one appeared on the other in about
one second, in both directions, with revision numbers climbing from 2 to 4.

The v43 suite gained a test asserting that a demonstration copy is disposable and a working
copy is not. It now reports 159 assertions, not 156.

### 8.3 Layout at the sizes that matter

The Samsung Galaxy A11+ 5G presents a 360 by 780 CSS viewport at double density; a tablet
held upright is 800 by 1280. Both were driven in Chromium. Tables become labelled cards at
860 px and below (previously 700, which left a crushed seven-column table on an upright
tablet). Dialogs become full pages at 700 px and below, with the action row pinned to the
bottom. The landing page keeps its two columns down to 760 px and scales its headline with
the height of the screen. No horizontal overflow was found on 360 x 780, 800 x 1280,
1280 x 800 or 800 x 360.

### 8.4 What a person can now change

Settings, Network and devices, Live update: the state of the refresh, the count of updates
taken in the session, the host revision, a switch to turn the refresh off for that device,
and a choice of half a second, one second or two seconds. The organisation's default is half
a second, and it is what a fresh installation uses.
