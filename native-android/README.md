# CareLink Native Android — migration preview

This is a separate Kotlin application using Android framework views. It does not load the website, launch Brave, use a WebView, or require a browser. The existing web app and TWA workflow are unchanged.

## Honest delivery status

This is **not the completed CareLink system**. This first increment supplies a native workspace, module directory, fictional patient registration/list/detail, and sample visit recording/history. All other directory entries explicitly say they are pending, not working features. No authentication, production API integration, clinical assessment logic, offline database, or real-patient security certification has been implemented. Do not use for care delivery or enter personal data. Preview changes are in memory (including activity state restoration) and disappear when the process is reset.

## Build and test

Use Java 17, Android SDK 35 and Gradle 8.11.1:

```
cd native-android
gradle :app:assembleDebug :app:lintDebug
```

Alternatively, after this branch is published, run **Build Native Android Preview** in GitHub Actions on this branch. Download **CareLink-Native-Preview-APK**, unzip and install. This is a debug-signed test app, with a distinct application ID from the old wrapper; not a production or Play Store release. Debug keys on hosted runners are not stable release keys.

No Java/Android SDK is available in the editing sandbox; compilation and device testing are still required. A static source check does not establish that the APK compiles.

Manual acceptance: launch with no browser installed; navigate workspace/patients/visits; add a fictional label; reject empty labels; record a visit; rotate; inspect history; cancel and confirm clearing; check large fonts/TalkBack. Verify no request to live backend and no real data in the app.

## Full migration scope (pending beyond preview)

- Identity: login, role enforcement, session expiry and access audit.
- Care: patient registry, households, assessment forms, Omaha care planning, review, referrals, discharge, TB and pharmacy.
- Operations: scheduling, team handovers, inventory and procurement.
- Organisation: staff/leave, costing/finance, reports/indicators, governance, documents, media, meetings and communication.
- System: encrypted offline database, authenticated sync/conflict resolution, backup, settings, release signing and accessibility tests.

Each workflow requires mapping the existing web business rules and API permissions, native implementation, automated tests and device acceptance. API integration must not bypass server authorization. Before real records are used: threat modelling, encrypted storage, backup exclusion, access controls, audit trails and validation of clinical logic are release gates. No clinical recommendations are generated by this preview.

## Additional native draft forms

The preview now includes twelve module-specific draft entry/list/detail/delete forms and a sample activity count report. Required-field/length checks, non-negative costing amounts and positive whole-number requisition quantities have unit tests. Drafts survive activity recreation but are not durable records. They deliberately do not execute prescriptions, approvals, payments, messages, referrals or stock movements. This expands native interface coverage; it is not full business-rule parity. Live role-based access and secure sync remain release blockers.

The build now uses the runner's existing Android SDK instead of the failing setup action. CI compiles, runs unit tests and lints. Build failures are copied into annotations and a diagnostic artifact so they can be investigated without repeatedly asking for screenshots.
